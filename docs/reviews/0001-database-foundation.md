# 0001: Review of the database foundation (setup step 8)

- **Date:** 2026-10-14
- **Branch:** `build/database`
- **Reviewers:** `reviewer` (security, CI, tests) and `domain-guardian` (domain and ADRs) subagents
- **Result:** no blockers. Nothing was exploitable yet, since no tenant table existed. Everything
  that could be fixed on the branch was fixed there, as `--fixup` commits squashed into the commit
  each change belongs to; the open items below need a decision or an action from the owner.

Findings were confirmed against a real Postgres where possible, in transactions that were rolled
back. Fixes started with a failing test, and the guard test was checked by breaking it on purpose.

## Fixed on the branch

| #   | Finding                                                                                                                                                                                                    | Fix                                                                                                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | The owner role was the Docker image's superuser, so forced RLS never applied to it locally or in CI, unlike Neon. A data migration could pass CI and change no rows in production                          | The image's `postgres` superuser only bootstraps; `squadio_owner` has no superuser or `BYPASSRLS`. Test fixtures now set a tenant context. A test checks the owner              |
| 2   | The guard test missed views and materialized views over tenant tables (both returned every organization's rows to the app) and accepted any policy that mentioned the tenant function, such as `… OR true` | The guard flags views without `security_invoker`, every materialized view, and any policy that is not exactly the tenant check, with an explicit exceptions list                |
| 3   | New functions were executable by `PUBLIC`, so an owner's `SECURITY DEFINER` function could read across organizations                                                                                       | The first migration revokes `EXECUTE` on new functions from `PUBLIC`, globally (a per-schema revoke does not work). A test checks it                                            |
| 4   | Roles created from Neon's console may inherit its admin role, which bypasses RLS                                                                                                                           | ADR 0004: `squadio_app` is created with SQL. A test fails if the app is a member of any role with superuser or `BYPASSRLS`, or can create objects                               |
| 5   | Database tests ran in the development database and could wipe its data once seeds exist                                                                                                                    | A separate `squadio_test` database for tests and CI                                                                                                                             |
| 6   | In CI's per-commit loop, the database kept the previous commit's state, so a commit could pass on an older migration                                                                                       | The loop recreates the database before each commit's database tests                                                                                                             |
| 7   | Foreign keys are checked without RLS, so a row could point at another organization's row                                                                                                                   | ADR 0004 and AGENTS.md require `unique (organization_id, id)` and composite foreign keys between tenant tables                                                                  |
| 8   | The local-only check on test URLs could be fooled with a `?host=` parameter                                                                                                                                | It also rejects `host` and `hostaddr` parameters; tested                                                                                                                        |
| 9   | `DATABASE_OWNER_URL` was set for every CI job                                                                                                                                                              | Only the jobs that migrate or run database tests get it                                                                                                                         |
| 10  | The app's connection pool would be recreated on every hot reload in `next dev`                                                                                                                             | Cached on `globalThis` outside production; tested                                                                                                                               |
| 11  | A failing test could leave a spy in place for later tests                                                                                                                                                  | `restoreMocks` in the database test config                                                                                                                                      |
| 12  | The app could create temporary tables and connect to the bootstrap database                                                                                                                                | Both revoked from `PUBLIC`; tested                                                                                                                                              |
| 13  | Money must be `numeric`, but nothing checked it                                                                                                                                                            | The guard fails on floating-point columns                                                                                                                                       |
| 14  | ADR 0004 had a wrong signature, said the owner "cannot skip the policies silently" (it sees no rows instead), and pointed at an unversioned plan                                                           | ADR 0004 rewritten with every decision above                                                                                                                                    |
| 15  | The domain model, AGENTS.md and the glossary did not mention the tenancy rules, "rate access" or "tenant context"                                                                                          | Added to `docs/domain.md`, `AGENTS.md` and `docs/glossary.md`                                                                                                                   |
| 16  | The `guard-bash` hook, older than this branch, let `.env` reads through after `<`, `(` or a backtick: `cat <.env`, `$(cat .env)`                                                                           | The owner changed the hook, since the permission classifier stops the agent from editing its own hooks. Globs such as `.env*` stay allowed, so `.gitignore` can still list them |

## Open: decisions for the owner

| #   | Finding                                                                                                                                                                                                               | Options                                                                                                                                                                                                               | When                                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| A   | **Rate access is not enforced by the database.** RLS separates organizations, but inside one, any query returns cost and salary columns. The rule "without rate access, no costs or margins" depends on the app alone | (a) Enforce it in the app, in one data-access layer that leaves out cost fields, with tests. (b) Enforce it in the database: costs in their own tables with a second policy on something like `app.has_rate_access()` | ADR 0005, before the first cost table |
| B   | **Frozen rates on a scenario carry costs.** Stored on the scenario row, every scenario read would send costs to users without rate access                                                                             | Model them as their own entity (scenario, category, cost per hour, sell rate), covered by decision A                                                                                                                  | With ADR 0005                         |
| C   | **Better Auth's tables.** Some have no `organization_id` (users, sessions) and some are read across organizations ("my organizations"), so forced, fail-closed RLS would break them                                   | Their own schema with their own role or policies, or the guard's allowlist                                                                                                                                            | When auth lands (v0.5)                |
| D   | **Global reference data** (starting templates with indicative salaries, the holiday calendar)                                                                                                                         | Read-only global tables on the allowlist, or constants in code copied into each organization                                                                                                                          | With the first such table             |
| E   | **Money in Postgres:** does `numeric` hold euros (`numeric(p,2)`) or cents, and how does Drizzle map it (pg returns `numeric` as a string) to integer cents?                                                          | Decide in `docs/domain.md`                                                                                                                                                                                            | Before the first money column         |
